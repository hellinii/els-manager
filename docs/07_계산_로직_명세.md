## 1. 목적 및 적용 범위

본 문서는 시스템이 수행하는 모든 도메인 계산의 알고리즘을 정의한다. 조건 판정, 수령액 산출, 과세 금융소득 산정, 금융소득종합과세, 건강보험료, 연도별 집계를 다룬다.

**본 문서는 알고리즘을 정의하며 상수값을 정의하지 않는다.** 세율·요율 등 법령 기반 상수는 `tax_constants` / `tax_brackets`에 연도별로 저장된다(DOC-002 M-05). 본문에 등장하는 구체적 수치는 2026년 기준 예시이며, 구현 시 상수를 하드코딩해서는 안 된다.

10장의 검증 케이스는 **회귀 테스트로 고정한다**(K-08). 계산 로직 변경 시 해당 케이스가 모두 통과해야 한다.

> **면책:** 본 시스템의 세액 산출은 추정·계획 목적이며 세무 신고 자료가 아니다(DOC-001 C-04).

## 2. 표기 규약

| 기호 | 의미 |
|---|---|
| `P` | 투자원금 (principal) |
| `r` | 연쿠폰율 (annual_coupon_rate) |
| `m` | 평가주기 개월 수 |
| `n` | 차수 (round_no) |
| `B(n)` | n차 조기상환 배리어 |
| `L(n)` | n차 리자드 배리어 |
| `W` | 워스트오브 (worst-of ratio) |
| `F` | 특정 소유자·연도의 과세 금융소득 총액 |
| `A` | 금융소득 외 종합소득 과세표준 |
| `T(x)` | 종합소득세 누진 산출세액 함수 (5.1) |

**단위 규약**

- 비율은 소수로 정규화하여 저장·계산한다 (90% → `0.9`). DOC-002 M-04.
- 금액은 원 단위 정수로 취급한다. 중간 계산은 고정소수점으로 수행하고 최종 표시 시 반올림한다.
- 모든 금액 계산에서 부동소수점 연산을 금지한다. DOC-002 M-03.

**주입 상수**

본문의 알고리즘은 아래 상수를 **인자로 주입받는다**(DOC-010 DEP-03). 값은 `tax_constants`·`tax_brackets`에서 연도별로 조회하며, 계산 모듈이 직접 조회하거나 하드코딩하지 않는다. 2026년 열의 값은 검증 케이스(10장)의 기준이며 명세의 일부가 아니다.

| 기호 | `tax_constants.key` | 표준 용어 | 2026년 |
|---|---|---|---|
| `separateTaxationRate` | `separate_taxation_rate` | 분리과세율 | 0.154 |
| `separateTaxationIncomeTaxRate` | `separate_taxation_income_tax_rate` | 분리과세 소득세율 | 0.14 |

누진세율 구간은 `tax_brackets`에서 `(lowerBound, rate, progressiveDeduction)` 목록으로 주입받는다(5.1).

> **분리과세율과 분리과세 소득세율을 분리하는 이유.** 15.4%는 소득세 14%와 지방소득세 1.4%의 합이다. 비교과세(5.2)의 방식①·방식②는 **소득세만** 산출한 뒤 5.3에서 지방소득세를 별도로 가산하므로 소득세분 14%를 쓴다. 반면 원천징수액(5.5)은 이미 지방세를 포함한 실제 징수액이므로 15.4%를 쓴다. 두 값을 하나의 상수로 두면 어느 한쪽이 반드시 틀린다.

> **직장가입자·피부양자 문턱을 종합과세 기준금액과 분리하는 이유.** 2026년 기준 세 값이 모두 2,000만원이나, 앞의 둘은 국민건강보험법상 부과 문턱이고 뒤는 소득세법상 종합과세 기준금액이다. 근거 법령이 달라 함께 개정된다는 보장이 없으므로 별도 상수로 관리한다.

## 3. 조건 판정

### 3.1 워스트오브 (Worst-of)

기초자산 중 기준가 대비 등락률이 가장 낮은 자산의 비율.

```
W = min( currentPrice(a) / basePrice(a) )   for a in underlyings(els)
```

**전제**

- `currentPrice`는 `asset_prices`의 최신 `as_of_date` 값이다.
- 기준가와 현재가는 동일 통화이므로 비율 계산에서 통화가 상쇄된다. 환율 변환은 수행하지 않는다(DOC-002 D-03).
- 어느 하나의 기초자산이라도 현재가가 없으면 `W`는 산출 불가(`null`)이며, 조건 판정 결과도 `null`로 처리한다. 임의의 기본값을 대입해서는 안 된다.
- **기초자산이 0건이면 산출 불가가 아니라 전제조건 위반이다.** `null`을 반환하지 않고 **거부한다.**

> **0건과 E-01의 `null`은 성질이 다르다.** E-01의 `null`은 시세가 수집되면 값이 생기는 **일시적** 상태다. 기초자산 0건은 DOC-002 I-07이 금지한 **구조적** 위반이며 시세를 기다려도 해소되지 않는다. 둘을 같은 `null`로 반환하면 화면이 "시세 없음"을 표시하면서 영원히 오지 않을 시세를 기다리게 된다. §9.1이 E-01의 `null`(판정 보류)과 E-05의 `null`(판정 대상 아님)을 구분한 것과 같은 이유다.
>
> 거부는 §9의 예외 처리 대상이 아니다 — E-표는 **발생할 수 있는 상황**의 처리 규칙이고, 0건은 발생해서는 안 되는 입력이다. `tax_brackets`가 빈 목록으로 주입되는 경우를 시드 오류로 보고 거부하는 것(§5.1)과 같은 부류다.

### 3.2 조기상환 조건

n차 평가일에 대하여:

```
조기상환 충족  ⟺  W ≥ B(n)
```

### 3.3 리자드 조건

n차에 리자드가 정의된 경우(`lizard_barrier IS NOT NULL`)에만 평가하며, **조기상환 조건이 충족되지 않았을 때에만** 판정한다.

```
리자드 충족  ⟺  W < B(n)
              ∧  W ≥ L(n)
              ∧  ( lizard_requires_no_ki = false  ∨  KI 미터치 )
```

판정 우선순위는 다음과 같다.

```
1. W ≥ B(n)          → 조기상환 (EARLY)
2. 리자드 충족        → 리자드상환 (LIZARD)
3. 그 외              → 다음 차수로 이월
```

### 3.4 KI 상태

```
KI 미설정   ⟺  ki_barrier IS NULL          (노낙인 상품)
KI 터치됨   ⟺  ki_touched_at IS NOT NULL
KI 미터치   ⟺  위 두 경우가 아님
```

**보조 판정.** 수집된 시세로 `W < ki_barrier`가 관측되면 터치 후보로 표시하고 사용자 확인을 요청한다. 시스템이 자동으로 `ki_touched_at`을 확정하지 않는다(DOC-002 D-04). 관측 방식(`ki_observation`)이 `CONTINUOUS`인지 `CLOSING`인지에 따라 요구되는 데이터가 다르므로, `ki_barrier`가 있으면 관측 방식도 반드시 있어야 한다(DOC-002 I-11).

> **`ki_barrier IS NULL`이면 `ki_touched_at`을 보지 않는다.** 위 표의 첫 줄부터 `ki_barrier`가 있는 상품을 전제하며, E-06이 노낙인 상품의 KI 판정을 생략하고 리자드의 KI 요구 조건을 항상 충족으로 처리한다. 따라서 `ki_barrier`가 없는데 `ki_touched_at`이 기록된 행은 **그 기록이 판정에서 완전히 무시되고**, 리자드 상환이 잘못 판정되어 수령액이 어긋난다. 이 명세는 그런 행의 존재를 전제하지 않으므로 DOC-002 I-15가 저장 시점에 막는다 — 판정 알고리즘을 바꾸는 것이 아니라 입력의 정의역을 좁히는 것이다.

**표시 등급 (참고)**

| 조건 | 상태 |
|---|---|
| `ki_touched_at IS NOT NULL` | KI 터치 |
| `W ≤ ki_barrier` | KI 이하 (확인 필요) |
| `W ≤ ki_barrier × 1.1` | 주의 |
| 그 외 | 안전 |

## 4. 수령액 및 과세 금융소득

### 4.1 예상 수령액 (미상환 상품)

n차에 상환된다고 가정할 때의 세전 수령액.

```
grossExpected(n) = P × ( 1 + r × (m × n) / 12 )
```

**적용 쿠폰율.** 위 식의 `r`은 상수가 아니라 판정 결과(§3.3)에 따라 선택된 값이다.

```
applicableCouponRate(condition, r, lizardCouponRate)
  = r                     if condition = EARLY
  = lizardCouponRate      if condition = LIZARD
```

- `CARRY_OVER`는 해당 차수에 상환되지 않으므로 적용 쿠폰율이 정의되지 않는다. 호출 대상이 아니다.
- 아직 평가일이 도래하지 않은 차수는 판정값이 없으므로 **`EARLY`(정상 조기상환)를 가정한다.** 예상 수령액은 추정값이며, 리자드 상환을 가정하려면 호출부가 `LIZARD`를 명시한다.
- `condition = LIZARD`이고 해당 차수의 `lizard_coupon_rate`가 `NULL`이면 **오류로 처리한다.** 원금만 상환되는 리자드 변형은 `0`으로 표기하며 `NULL`로 표기하지 않는다(Q-04). `NULL`을 `0`이나 `r`로 임의 대체하면 수령액이 실제와 어긋난다 — 전자는 과소, 후자는 과대 추정이다.

### 4.2 확정 수령액 (상환 완료 상품)

`redemptions.gross_amount`를 그대로 사용한다. 시스템 추정값으로 대체하지 않는다(DOC-002 A-04).

### 4.3 과세 금융소득

```
if account_type = TAX_FREE:
    taxableIncome = 0                      # 비과세 계좌는 종합과세 대상 제외

elif 상환 완료:
    taxableIncome = redemptions.taxable_income      # 증권사 확정값

else:  # 미상환 (추정)
    taxableIncome = max(0, grossExpected(n) − P)
```

### 4.4 손실 상환의 취급

**ELS 손실은 다른 금융소득과 통산되지 않는다.** 따라서 손실 상환(`MATURITY_LOSS`)의 과세 금융소득은 음수가 아니라 `0`이다.

```
포트폴리오 손익  =  gross_amount − P        (음수 가능)
과세 금융소득    =  0                        (음수 불가)
```

예: A 상품에서 1,000만원 손실, B 상품에서 2,000만원 이익이 발생한 경우

| 항목 | 값 |
|---|---|
| 포트폴리오 순손익 | +1,000만원 |
| 과세 금융소득 | **2,000만원** (1,000만원이 아님) |

이 분기는 사용자가 오해하기 쉬우므로 UI에서 두 값을 별도 항목으로 표시한다.

## 5. 금융소득종합과세

### 5.1 누진 산출세액 함수

`tax_brackets`에서 과세표준 `x`가 속한 구간의 세율과 누진공제를 조회한다.

```
T(x) = 0                                          if x ≤ 0
     = x × rate(x) − progressiveDeduction(x)      otherwise
```

**2026년 기준 구간 (예시 — 실제 값은 `tax_brackets`에서 조회)**

| 과세표준 하한 | 세율 | 누진공제 |
|---|---|---|
| 0 | 6% | 0 |
| 1,400만 | 15% | 126만 |
| 5,000만 | 24% | 576만 |
| 8,800만 | 35% | 1,544만 |
| 1억 5,000만 | 38% | 1,994만 |
| 3억 | 40% | 2,594만 |
| 5억 | 42% | 3,594만 |
| 10억 | 45% | 6,594만 |

### 5.2 비교과세

금융소득이 종합과세 기준금액을 초과하는 경우, 두 방식으로 산출한 세액 중 **큰 값**을 적용한다. 이하 `k`는 2장의 주입 상수 집합을 가리킨다.

```
방식 ①(분리 기준) = F × k.separateTaxationIncomeTaxRate + T(A)
방식 ②(종합 기준) = k.comprehensiveTaxationThreshold × k.separateTaxationIncomeTaxRate
                  + T( max(0, F − k.comprehensiveTaxationThreshold) + A )

산출세액 = max( 방식①, 방식② )
```

두 방식은 **소득세만** 산출한다. 지방소득세는 5.3에서 가산하므로 여기서 15.4%가 아니라 소득세분 14%를 쓴다(2장 참조).

**금융소득 귀속세액**(국세)은 전체 산출세액에서 금융소득이 없었을 때의 세액을 차감하여 구한다.

```
def financialIncomeTax(F, A, k):
    if F ≤ 0:
        return 0
    if F ≤ k.comprehensiveTaxationThreshold:
        return F × k.separateTaxationIncomeTaxRate      # 분리과세로 종결

    method1 = F × k.separateTaxationIncomeTaxRate + T(A)
    method2 = k.comprehensiveTaxationThreshold × k.separateTaxationIncomeTaxRate
            + T( max(0, F − k.comprehensiveTaxationThreshold) + A )
    return max(method1, method2) − T(A)
```

**기준금액 이하의 조기 반환은 생략할 수 없다.** 비교과세식을 기준금액 이하 구간까지 확장하면 틀린 값이 나온다. `F = 10,000,000`, `A = 0`인 경우 방식① = 1,400,000, 방식② = 2,800,000이므로 `max(①,②) − T(A) = 2,800,000`이 되지만, 정답은 원천징수로 종결되는 1,400,000이다. 방식②는 기준금액까지를 항상 전액 과세한 것으로 계산하므로 기준금액 미달 구간에서 성립하지 않는다. 두 방식이 교차하는 구간은 `F > k.comprehensiveTaxationThreshold`뿐이다.

**방식①·방식②의 표시.** `F ≤ k.comprehensiveTaxationThreshold`인 경우 비교과세를 적용하지 않으므로 두 방식 값은 의미가 없다. 화면·계약 계층에는 값이 아니라 **미적용(null)** 으로 전달한다(DOC-011 §4.6).

**`A`의 취급.** `A`가 미입력(null)인 경우와 `0`인 경우의 결과는 동일해야 한다. 구현 시 `A = coalesce(A, 0)`으로 정규화한다.

### 5.3 지방소득세

지방소득세는 소득세액에 `localIncomeTaxRate`(2026년 10%)를 곱한 값이다.

```
localIncomeTax(F, A) = financialIncomeTax(F, A) × k.localIncomeTaxRate
totalTax(F, A)       = financialIncomeTax(F, A) × ( 1 + k.localIncomeTaxRate )
```

### 5.4 최종 부담률

```
effectiveRate(F, A) = totalTax(F, A) / F        (F > 0)
                    = 0                          (F ≤ 0)
```

### 5.5 추가납부 예상액

상환 시점에 원천징수가 이미 이루어졌으므로, 종합과세 확정 세액과의 차액만 추가 납부한다. 원천징수액은 지방소득세를 포함한 실제 징수액이므로 `separateTaxationRate`(2026년 15.4%)를 쓴다.

```
withheld(F)         = F × k.separateTaxationRate
additionalTax(F, A) = max( 0, totalTax(F, A) − withheld(F) )
```

**중요 — 추가납부 0이 정상인 경우.** `A`가 작을 때 방식①이 방식②보다 크면 실효세율이 원천징수율로 유지되어 추가납부가 발생하지 않는다. 이는 오류가 아니다.

다른 종합소득이 없는 경우(`A = 0`) 추가납부가 처음 발생하는 지점은 **F = 77,600,000원**이다. 2026년 상수로 유도하면 다음과 같다.

```
방식① = 방식②
F × 0.14 = 20,000,000 × 0.14 + (F − 20,000,000) × 0.24 − 5,760,000
0.14F − 2,800,000 = 0.24F − 10,560,000
0.10F = 7,760,000
F = 77,600,000
```

이 임계값은 `A`에 따라 이동하므로 하드코딩하지 않는다. 위 값은 검증 케이스(10장)의 기준점으로만 사용한다.

### 5.6 구간별 실질 한계 부담률

금융소득이 1원 증가할 때의 추가 부담률. 세금과 건강보험을 합산한다.

```
marginalRate(bracket) = bracketRate × ( 1 + k.localIncomeTaxRate )   # 지방소득세 포함
                      + k.healthInsuranceRate                        # 건강보험료율
                      + k.healthInsuranceRate × k.longTermCareRate   # 장기요양보험료
```

|---|---|---|---|---|
| 6% | 6.60% | 7.19% | 0.94% | **14.73%** |
| 15% | 16.50% | 7.19% | 0.94% | **24.63%** |

## 6. 건강보험료

### 6.1 가입유형별 산정 소득

```
def insuranceBase(F, type, k):
    if type = REGIONAL:      # 지역가입자
        return F if F > k.regionalIncomeThreshold else 0    # 초과 시 전액 반영
    if type = EMPLOYEE:      # 직장가입자
        return max(0, F − k.employeeNonWageThreshold)       # 보수외소득 초과분만
    if type = DEPENDENT:     # 피부양자
        return F if F > k.dependentIncomeThreshold else 0   # 초과 시 자격 상실 → 전액
    return 0                                                # NONE
```

문턱 구조가 유형별로 다르다는 점에 유의한다. 지역가입자는 `regionalIncomeThreshold`(2026년 1,000만원) 초과 시 **전액**이 반영되므로 문턱 부근에서 부담이 계단식으로 증가한다.

세 문턱은 2026년 기준으로 각각 1,000만·2,000만·2,000만원이나 **서로 다른 상수**다. 뒤의 두 값이 종합과세 기준금액과 같은 것도 우연이며, 근거 법령이 다르므로 하나의 상수로 공유하지 않는다(2장 참조).

### 6.2 보험료 산출

```
healthInsurance(F, type) = insuranceBase(F, type, k) × k.healthInsuranceRate
longTermCare(F, type)    = healthInsurance(F, type) × k.longTermCareRate
totalInsurance           = healthInsurance + longTermCare
```

장기요양보험료는 금융소득이 아니라 **건강보험료에** 비율을 곱한 값이다(DOC-005 §5).

### 6.3 산출값의 한계

지역가입자 보험료는 실제로는 주민등록세대 단위로 소득·재산을 합산하여 부과되나, 본 시스템은 세대 구성과 재산을 모델링하지 않는다. 따라서 산출값은 **개인의 금융소득만 반영한 추정치**이며 실제 부과액과 차이가 있다(DOC-001 A-06). 이 취지를 UI에 고지한다.

## 7. 연도별 집계

### 7.1 집계 단위

집계 키는 항상 **(소유자, 귀속연도)** 다. 사용자 간 합산은 어떤 경우에도 수행하지 않는다(DOC-002 D-02).

집계는 **평탄한 합산이 아니라 키별 분할**로 정의한다. 여러 소유자·연도가 섞인 항목 집합을 받으면 키별로 나누어 각각 집계하며, 서로 다른 키의 값이 하나의 합계에 들어가는 경로를 두지 않는다.

```
groupByOwnerYear(items) = [ (key, { item ∈ items | key(item) = key }) | key ∈ distinct(key(items)) ]
```

단일 키 집계는 키를 **명시적 인자로 받고**, 키와 다른 항목이 섞여 있으면 거부한다.

```
aggregateFinancialIncome(key, items) = ERROR         if ∃ item ∈ items : key(item) ≠ key
                                     = (key, F)      otherwise
```

집계 결과는 항상 키를 동반한다. 값만 반환하면 이후 단계에서 어느 소유자·연도의 값인지 알 수 없고, 두 사람의 결과를 같은 변수에 담는 실수가 드러나지 않는다.

> **왜 키를 인자로 받는가.** 항목 배열만 받고 "호출부가 이미 필터링했다"고 가정하면 규칙은 주석으로만 존재한다. 키를 명시하면 위반이 함수 경계에서 드러난다. 키가 컴파일 시점에 알려진 경우(리터럴·상수)에는 타입 수준에서 거부되고, 런타임 UUID인 경우에는 같은 규칙을 실행 시점에 검사한다. 두 방어는 대체 관계가 아니라 보완 관계다.

### 7.2 귀속연도 결정

```
상환 완료: year( redemptions.redemption_date )
미상환   : year( 적용 차수의 evaluation_date )
```

미상환 상품의 적용 차수는 사용자가 지정하지 않은 경우 **다음 도래 평가일의 차수**로 가정한다.

### 7.3 연도별 금융소득

```
F(owner, year) = Σ taxableIncome(els)                     # 해당 소유자·연도의 ELS
               + tax_profiles.other_financial_income      # ELS 외 금융소득
```

합산 대상은 §7.1의 키에 속한 항목뿐이다. `other_financial_income`도 `(owner, year)`에 귀속된 값이므로 다른 소유자·연도의 값을 더할 수 없다.

`A`는 `tax_profiles.other_income_base`에서 조회한다. `A` 역시 개인 단위이므로 `F`와 같은 소유자의 값이어야 한다.

### 7.4 세후 회수액

```
netProceeds(owner, year) = Σ gross(els) − F(owner, year) × effectiveRate(F, A)
```

비과세 계좌 상품은 `taxableIncome = 0`이므로 세액이 부과되지 않고 `gross`가 전액 반영된다.

## 8. 계산 파이프라인

화면 렌더링 시의 계산 순서. 하위 단계는 상위 단계의 결과에 의존한다.

```
1. 시세 조회        → asset_prices 최신값
2. 워스트오브 산출   → 상품별 W
3. 조건 판정        → 조기상환 / 리자드 / 이월, KI 상태   (보유중 상품만 — E-05)
4. 적용 차수 결정    → 사용자 지정 또는 다음 평가일        (경과 미상환 차수는 E-07)
5. 수령액 산출      → 확정값 또는 적용 쿠폰율 기반 추정값
6. 과세소득 산정     → 계좌유형·손실 규칙 적용
7. 연도별 집계      → (소유자, 연도) 키별 분할 — 키를 넘어 합산하지 않는다
8. 세액·보험료 계산  → 비교과세, 건강보험
9. 부담률·추가납부   → 표시값 산출
```

## 9. 예외 및 경계 처리

| ID | 상황 | 처리 |
|---|---|---|
| E-01 | 기초자산 현재가 누락 | `W = null`, 조건 판정 `null`. 화면에 "시세 없음" 표시 |
| E-02 | `F ≤ 0` | 모든 세액·보험료 `0` |
| E-03 | `A` 미입력 | `0`으로 정규화. 결과는 `A = 0`과 동일 |
| E-04 | `F ≤ comprehensiveTaxationThreshold` | 분리과세 종결. 방식①·② 미적용(`null`), 추가납부 `0`, 부담률 = `separateTaxationRate` |
| E-05 | 상환 완료 상품 | 조건 판정·시세 비교 수행하지 않음. **반환 계약은 §9.1** |
| E-06 | 노낙인 상품 (`ki_barrier IS NULL`) | KI 판정 생략, 리자드의 KI 요구 조건은 항상 충족으로 처리 |
| E-07 | 평가일이 과거이나 미상환 | 사용자에게 상환 처리 또는 이월 확인 요청. **반환 계약은 §9.2** |
| E-08 | 손실 상환 | 과세소득 `0`, 포트폴리오 손익은 음수 반영 |

E-05와 E-07은 "무엇을 하지 않는다" 또는 "사용자에게 요청한다"로만 기술되어 있어 반환값이 정의되지 않았다. 두 항목의 계약을 아래에서 확정한다.

### 9.1 E-05 반환 계약 — 상환 완료 상품

상태는 상환 레코드의 존재로 유도한다(DOC-002 §5.1). 조건 판정(§3.2·§3.3), KI 판정(§3.4), 시세 비교는 **보유중 상품에만 정의된다.**

```
asActive(params, redemption) = params     if redemption = NULL      # 보유중
                             = NULL       otherwise                 # 상환완료
```

판정 함수의 입력은 `asActive`의 반환값으로 한정한다. 상환 완료 상품에서는 `asActive`가 `NULL`을 반환하므로 판정 함수에 넘길 값이 애초에 존재하지 않는다.

| 대상 | 보유중 | 상환완료 |
|---|---|---|
| 조건 판정 (§3.2·§3.3) | `EARLY` / `LIZARD` / `CARRY_OVER`, 시세 없으면 `NULL` | **호출 불가** |
| KI 표시 등급 (§3.4) | `NO_KI` / `SAFE` / `WARNING` / `BELOW` / `TOUCHED`, 시세 없으면 `NULL` | **호출 불가** |
| KI 터치 후보 (§3.4 보조 판정) | `true` / `false` | **호출 불가** |

`asActive`가 `NULL`을 반환한 경우 호출부는 이를 **판정 생략**으로 표시한다. `CARRY_OVER`나 `SAFE` 같은 판정값으로 대체하지 않는다. 상환 완료 상품의 표시값은 판정 결과가 아니라 상환 실적(§4.2)이다.

> **`NULL`의 두 의미를 구분한다.** 판정 함수가 반환하는 `NULL`은 E-01(시세 없음 → 판정 보류)이고, `asActive`가 반환하는 `NULL`은 E-05(상환 완료 → 판정 대상 아님)다. 전자는 시세가 수집되면 값이 생기고, 후자는 영구적이다.

> **구현 방침.** "호출 불가"를 규율이 아니라 타입으로 강제한다. 판정 함수는 `asActive`만 부여할 수 있는 표식이 붙은 입력만 받으므로, 상환 완료 상품에 판정을 시도하는 코드는 컴파일되지 않는다.

### 9.2 E-07 반환 계약 — 평가일이 과거이나 미상환

```
overdueEvaluations(schedules, asOf, redemption)
  = []                                                        if redemption ≠ NULL
  = [ (schedule, daysOverdue) | evaluation_date < asOf ]       otherwise
                                                              (evaluation_date 오름차순)

daysOverdue = asOf − evaluation_date                          (양수)
```

- **상환 완료 상품은 빈 배열이다.** E-05가 우선한다. 상환 처리로 확인이 완결되었으므로 경과 차수를 다시 묻지 않는다.
- 평가일 당일은 경과로 보지 않는다. §7.2의 "다음 도래 평가일"과 경계를 공유한다.
- 경과한 차수를 **전부** 반환한다. 최근 1건만 반환하면 여러 차수가 연속으로 경과한 상품에서 앞 차수의 확인이 누락된다.
- 결과가 비어 있지 않은 상품은 "상환 처리 또는 이월 확인" 대상이다. **시스템이 이월을 자동 확정하지 않는다**(D-04와 같은 취지).
- 확인 이력을 저장하지 않으므로 조회 시마다 재산출된다(RD-06).

**`nextEvaluation`(§7.2)과의 관계.** 두 함수는 같은 평가일 목록을 서로 배타적인 두 구간으로 나눈다.

| 함수 | 대상 구간 | 반환 |
|---|---|---|
| `nextEvaluation` | `evaluation_date ≥ asOf` | 그중 최소 1건, 없으면 `NULL` |
| `overdueEvaluations` | `evaluation_date < asOf` | 전부, 없으면 `[]` |

`nextEvaluation`이 `NULL`이고 `overdueEvaluations`가 비어 있지 않으면 만기까지 전 차수가 경과했음에도 상환 실적이 없는 상태다. 적용 차수를 결정할 수 없으므로 귀속연도(§7.2)와 예상 수령액(§4.1)도 산출되지 않는다.

## 11. 미결정 사항

| ID | 항목 | 상태 | 비고 |
|---|---|---|---|
| RD-01 | 세액·보험료 절사 단위 | 미결 | 증권사 원천징수액과 원 단위 오차 발생. 실제 고지 기준 확인 필요. **P1 구현 방침:** 절사 단위를 인자로 주입하고 기본값은 §2의 원 단위(`{ unit: 1, mode: TRUNCATE }`). 단위가 확정되면 호출부 인자만 교체하면 되므로 계산 모듈은 재작성하지 않는다. 10장 검증 케이스는 기대값이 모두 정수라 단위 선택과 무관하게 통과한다 |
| RD-02 | 미상환 상품의 기본 적용 차수 | 미결 | "다음 평가일" 가정이 적절한지, 사용자 지정 UI 필요 여부 |
| RD-03 | 평가일 영업일 조정 규칙 | 미결 | 휴장일 처리. 현재는 사용자 수정에 의존 |
| RD-04 | 지역가입자 세대 합산 지원 | 미결 | v1 제외(A-06). 지원 시 세대 엔티티 필요 |
