## 1. 도메인 배경

ELS(주가연계증권, Equity-Linked Securities)는 기초자산 가격에 따라 손익이 결정되는 파생결합증권이다. 국내 개인 투자자가 접하는 스텝다운형 구조의 동작은 다음과 같다.

- 통상 6개월 주기로 **조기상환 평가**를 수행한다.
- 평가일에 **워스트오브**(기초자산 중 기준가 대비 수익률이 가장 낮은 자산의 비율)가 해당 차수의 **배리어** 이상이면, 원금과 경과 기간에 해당하는 쿠폰을 지급하고 상품이 종료된다.
- 배리어는 차수가 진행될수록 낮아진다(스텝다운). 예: 90-85-80-75-70-65.
- 조건 미충족 시 다음 평가일로 이월된다.
- **리자드(Lizard) 조건**: 특정 차수에서 조기상환 배리어를 충족하지 못하더라도, 별도로 정한 더 낮은 리자드 배리어 이상이면 축소된 쿠폰으로 조기 종료된다. 적용 차수·배리어·쿠폰율은 상품마다 다르며, 기간 중 KI 미터치를 함께 요구하는 변형도 존재한다.
- **KI(Knock-In) 배리어**: 기간 중 기초자산이 이 수준을 하회하면 원금 보장 성격이 소멸한다. 만기까지 회복하지 못하면 워스트오브 비율만큼 원금이 손실된다.

### 관리가 어려운 이유

| 구분 | 내용 |
|---|---|
| 구조 다양성 | 기초자산 수, 평가 차수, 배리어 스케줄, 리자드 유무, KI 수준이 상품마다 모두 다름 |
| 일정 분산 | 평가일이 상품별 발행일에서 파생되어 흩어져 있음 |
| 세금 결합 | 수익 전액이 배당소득으로 과세. 연간 금융소득 2,000만원 초과 시 종합과세로 전환되어 세부담이 비선형으로 증가 |

특히 마지막 항목 때문에 **"언제 얼마가 들어오는가"와 "그 해 세금이 얼마인가"는 분리해서 관리할 수 없다.** 개별 상품의 수익률만 보아서는 실제 수령액을 알 수 없으며, 연도 단위 합산 관점이 필수적이다.

### 과세·부과 단위

세부담을 산출하는 항목마다 합산 단위가 다르다. 이는 데이터 모델과 계산 로직의 파티션 기준을 결정하는 핵심 제약이다.

| 항목 | 합산 단위 | 근거 |
|---|---|---|
| 금융소득종합과세 | **개인별** (2,000만원 기준도 개인별 판정) | 소득세법상 개인 단위 과세 |
| 건강보험료 — 직장가입자 | **개인별** (보수외소득 기준) | — |
| 건강보험료 — 지역가입자 | **세대 단위 합산** | 국민건강보험법 제69조제5항 |

따라서 **세금 계산은 반드시 개인 단위로 분리되어야 한다.** 여러 사용자의 금융소득을 합산하여 2,000만원 기준에 적용하면 잘못된 결과가 산출된다.

단, 지역가입자 건강보험료는 실제로는 주민등록세대 기준으로 합산 부과되나 본 시스템은 세대 구성을 모델링하지 않는다. 해당 산출값의 성격은 A-06에서 정의한다.

## 2. 해결하려는 문제

| ID | 문제 | 설명 |
|---|---|---|
| P-01 | 상품 구조의 가변성 | 기초자산 수(1~4종), 평가 차수(4~8회), 배리어 스케줄, 리자드 조건이 상품마다 다름. 고정 구조로는 수용 불가하며 상품 구조 자체를 데이터로 표현해야 함 |
| P-02 | 일정 파악의 어려움 | 평가일은 발행일과 평가주기에서 파생됨. 보유 상품이 늘어날수록 "다음에 확인할 것"이 무엇인지 즉시 알기 어려움 |
| P-03 | 조건 판정의 복잡성 | 워스트오브 산출 → 차수별 배리어 대조 → 리자드 조건 확인 → KI 터치 여부 추적. 매번 수작업 계산 시 오류 발생 |
| P-04 | 시세 갱신 비용 | 조건 판정에 기초자산 현재가가 필요. 동일 기초자산이 여러 상품에 중복 포함되는 경우가 많아 수동 입력은 중복 작업 |
| P-05 | 상태 전이의 정합성 | 상환 완료 시 보유 → 실현 상태 전이 필요. 수작업 처리 시 이중 집계나 기록 누락 발생 |
| P-06 | 세금의 연도 귀속 | 종합과세는 연간 합산 기준. 상환 시점이 어느 연도에 속하는지에 따라 세부담이 크게 달라지며, 상환 시기 조정이 가능한 경우 의사결정에 직접 영향 |
| P-07 | 접근성·공유 | 확인이 필요한 시점(평가일 임박)과 확인 가능한 시점이 어긋남. 복수 사용자가 각자의 보유 현황을 관리할 수 있어야 함 |

## 3. 프로젝트 목적

| 구분 | 목적 |
|---|---|
| 주 목적 | 2장의 문제를 해소하는 웹 기반 ELS 관리 시스템 구축 |
| 부 목적 | 요구사항 정의부터 운영까지 전 주기 산출물을 갖춘 **포트폴리오 프로젝트**로서 설계·문서화 역량 증명 |

부 목적이 명시적으로 존재하므로, 본 프로젝트는 동작하는 코드만이 아니라 **문서 산출물 자체를 결과물로 취급한다.** 따라서 통상 개인 프로젝트에서 생략되는 데이터 모델링, 아키텍처 결정 기록(ADR), 계산 로직 명세, 테스트 계획, 운영 설계를 정식 산출물로 작성한다.

## 4. 타깃 사용자

| 구분 | 사용자 | 특성 | 주요 니즈 |
|---|---|---|---|
| Primary | 본인 | ELS 다건 보유, 세금 계획 목적, 개발자 | 정확한 세금 예측, 빠른 입력, 연도별 시뮬레이션 |
| Secondary | 가족 A | 스프레드시트 조작에 부담, 결과 확인 중심 | 언제 얼마가 들어오는지, 세금은 얼마인지 |
| Secondary | 가족 B | 모바일 중심 사용 | 평가일 임박 여부, 현재 상태 확인 |

**공통 특성:** 매일 쓰는 도구가 아니다. 평가일 전후와 연말 세금 점검 시점에 집중적으로 사용하는 **저빈도·고중요 도구**이므로, 오랜만에 접속해도 현재 상황이 즉시 파악되는 화면 설계가 요구된다.

## 6. 범위 (Scope)

### 6.1 In Scope — v1

| ID | 기능 영역 | 설명 |
|---|---|---|
| S-01 | ELS 등록·수정·삭제 | 기초자산 N종, 상환차수 N회 가변. 배리어 스케줄(스텝다운), KI 배리어, **리자드 조건**(적용 차수·배리어·쿠폰) 입력 |
| S-02 | 평가일정 관리 | 발행일·평가주기 기반 차수별 평가일 자동 생성, D-day 산출 |
| S-03 | 시세 조회 | 기초자산 시세 자동 조회, 수동 입력 폴백 |
| S-04 | 조건 판정 | 워스트오브 산출, 차수별 조기상환 조건 충족 여부, **리자드 조건 충족 여부**, KI 배리어 상태 |
| S-05 | 상환 처리 | 상태 전이(보유 → 실현). **상환 유형 구분: 조기상환 / 리자드상환 / 만기상환(이익) / 만기상환(손실)**. 실수령액 및 과세표준 직접 입력 지원 |
| S-06 | 세금 계산 | 금융소득종합과세 계산, 연도별 귀속 합산, 분리과세 대비 비교 |
| S-07 | 건강보험료 | 가입 유형별 산정, 구간별 실질 부담률 |
| S-08 | 타임라인 | 연도별 세전/세후 회수, 추가납부 예상액, 누적 자산 추이 |
| S-09 | 대시보드 | 임박 평가일, 총자산, 손익, 부담률 요약 |
| S-10 | 사용자·권한 관리 | 인증. **데이터 소유 단위는 개인.** 조회는 전체 사용자에게 허용(가족 간 현황 공유), **생성·수정·삭제는 소유자 본인만** 가능 |
| S-11 | 반응형 UI | 모바일·데스크톱 대응 |

**S-05 보충.** 만기 손실이 발생한 경우 원금 대비 실제 수령액이 감소하므로, 시스템이 산출한 예상값이 아닌 **실제 수령액을 사용자가 직접 입력**할 수 있어야 한다. 손실 상환은 과세 대상 배당소득이 발생하지 않으므로 세금 계산에서 별도로 취급된다(상세 규칙은 계산 로직 명세에서 정의).

### 7.1 제약사항

| ID | 구분 | 내용 |
|---|---|---|
| C-01 | 비용 | 무료 티어 내 운영 (호스팅·DB·시세 API) |
| C-02 | 인력 | 1인 개발, 학업·연구 병행 |
| C-03 | 시세 API | 무료 한도 존재 → 일 배치 갱신, 폴백 필수 |
| C-04 | 법적 성격 | 세금 계산은 **추정·계획 목적**이며 세무 신고 자료가 아니다. 실제 신고는 홈택스·세무 전문가 확인이 필요하다는 고지를 UI에 노출한다 |

### 7.2 가정

| ID | 내용 |
|---|---|
| A-01 | 동시 사용자 10명 이하. 대규모 트래픽 대응 설계는 불필요 |
| A-02 | 세법·보험요율은 연도별로 변경된다. 상수 하드코딩을 금지하고 설정값으로 분리한다 |
| A-03 | 기초자산은 해외 상장 주식 중심이나, 국내 지수·종목도 입력 가능해야 한다 |
| A-04 | 상환 실적의 최종 기준값(실수령액·과세표준)은 증권사가 제공하는 값이며, 시스템 산출값은 예측치로 취급한다 |
| A-05 | 사용자 등록은 폐쇄형(초대 기반)이다. 따라서 별도 그룹 엔티티 없이 전체 사용자 간 조회를 허용해도 무방하다. 불특정 다수에게 개방할 경우 그룹 단위 접근 제어가 필요하며, 이는 범위 변경 사유에 해당한다 |
| A-06 | 지역가입자 건강보험료는 실제로는 주민등록세대 단위로 소득·재산을 합산하여 부과되나, 본 시스템은 세대 구성과 재산을 모델링하지 않는다. 산출값은 **개인의 금융소득만 반영한 추정치**이며 실제 부과액과 차이가 있음을 UI에 고지한다 |
